# Лист — агент поддержки интернет-магазина

Агент на **LangChain `create_agent`** с инструментами и RAG помогает менеджеру разобрать обращение покупателя:

1. находит правило в регламентах магазина;
2. готовит черновик ответа и вопросы-уточнения;
3. предлагает заявку ответственному сотруднику.

Заявка создаётся только после подтверждения человеком, ответ покупателю автоматически не отправляется.

Стек: LangChain/LangGraph, OpenAI (LLM + embeddings), Qdrant (гибридный поиск), FastAPI, SQLite, Streamlit.

**[Архитектура и устройство агента — spec.md](spec.md)**

## Быстрый старт

Нужны Python 3.11–3.14, [uv](https://docs.astral.sh/uv/getting-started/installation/) и ключ OpenAI (или совместимого провайдера).

```powershell
Copy-Item .env.example .env      # Linux/macOS: cp .env.example .env
# впишите OPENAI_API_KEY в .env
powershell -ExecutionPolicy Bypass -File .\run-streamlit.ps1
```

Откройте **http://127.0.0.1:8501**. API запускается внутри процесса Streamlit. Вручную или на Linux/macOS:

```sh
uv sync --locked
uv run streamlit run streamlit_app.py
```

Альтернативный HTML-интерфейс с отдельным API: `run.ps1` (или `uv run uvicorn app.main:app --host 127.0.0.1 --port 8000`), затем http://127.0.0.1:8000. Схемы API — `/docs`. Не запускайте оба варианта на одном `DATA_DIR`. Для уже работающего API задайте `AGENT_API_URL=http://127.0.0.1:8000` перед запуском Streamlit.

Без `OPENAI_API_KEY` приложение не стартует: агент всегда работает с реальной моделью. Вызовы оплачиваются по тарифу провайдера. Один разбор обращения — около 4 вызовов `gpt-4.1-mini` и ~10k токенов.

## Первый сценарий

1. Во вкладке «База знаний» нажмите «Загрузить пример магазина»: появятся четыре регламента «Лист». Повторная загрузка не создаёт дубликатов.
2. Во вкладке «Обращение» выберите «Неисправные наушники».
3. Агент вызывает `rag_search`, затем `publish_support_draft`. В карточке есть черновик, уточнения, ответственный и ссылка на регламент `defects.md`. Журнал действий показывает каждый вызов модели и инструмента.
4. Отредактируйте черновик и нажмите «Подготовить заявку». Агент вызовет `create_ticket`, а задача остановится в ожидании подтверждения.
5. Подтвердите, измените или отклоните. Запись появится во вкладке «Заявки» только после подтверждения.

Свои документы (TXT, MD, CSV, PDF с текстом, DOCX, PPTX) загружаются в той же вкладке. Агент отвечает по ним, а если правила не нашёл, передаёт вопрос человеку (`manual_review`), ничего не обещая.

Полезные запросы:

* «Какие документы есть в моей базе знаний?» — вызывает `list_knowledge_documents`;
* «Запомни: отвечать кратко» — `save_memory` с подтверждением;
* `/ticket Текст` — предложить заявку.

## Конфигурация

Все переменные с комментариями перечислены в [.env.example](.env.example). Главные из них:

* `OPENAI_API_KEY`, `OPENAI_BASE_URL`;
* `MODEL_FAST`, `MODEL_REASONING`;
* `EMBEDDING_MODEL`, `EMBEDDING_DIMENSIONS`;
* `QDRANT_URL` (пусто — встроенный Qdrant);
* `DATA_DIR`;
* `APP_TOKEN`;
* бюджеты `MAX_*`;
* `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY`, `LANGFUSE_BASE_URL` (необязательный трекинг).

После смены embedding-модели или размерности загрузите документы заново: векторы разных моделей несовместимы.

### Трекинг в Langfuse

Задайте оба ключа в `.env` и перезапустите приложение. Каждая задача становится отдельным trace `support-run`: шаги графа, вызовы моделей с токенами и инструменты. Беседа — это session, владелец — user, продолжение после подтверждения остаётся в том же trace. Вызовы embeddings в trace не попадают; поиск виден как инструмент `rag_search`.

В Langfuse уходит текст обращений, фрагменты документов и ответы модели. E-mail и секреты маскируются (`app/security.py`), а имена, телефоны и адреса — нет, поэтому не включайте трекинг на реальных данных покупателей без отдельного решения. Из ошибок в Langfuse попадает только их тип, без текста.

## Docker

Создайте `.env`, задайте `OPENAI_API_KEY` и длинный `APP_TOKEN`, затем:

```sh
docker compose up --build                       # API + Qdrant, http://127.0.0.1:8000
docker compose --profile streamlit up --build   # + Streamlit, http://127.0.0.1:8501
```

Данные хранятся в named volumes. Не добавляйте `-v` к `docker compose down`, если они нужны.

## Доступ и данные

* Без токена API доступен только с localhost. `APP_TOKEN` задаёт одного владельца, `APP_USERS_JSON` (`{"токен-A":"alice","токен-B":"bob"}`) — нескольких. Беседы, документы, память и заявки изолированы по владельцу.
* В `DATA_DIR` лежат `app.sqlite`, `checkpoints.sqlite`, `qdrant/`, `artifacts/`, `logs/agent.jsonl`. Для резервной копии остановите приложение и скопируйте каталог.
* Журнал действий агента: вкладка «Обращение» → «Журнал действий агента», `GET /api/runs/{id}/log` или `DATA_DIR/logs/agent.jsonl`. В журнал попадают только технические поля, без текстов запросов и ответов.

## Проверки

```sh
uv run pytest -q          # 64 теста, платный API не вызывается
uv run ruff check app tests
node --test tests/test_ui.cjs
```

Тесты подменяют `ChatOpenAI` и `OpenAIEmbeddings` заглушками (`tests/conftest.py`). Агентный цикл LangChain, Qdrant, SQLite, checkpoint и подтверждения при этом настоящие. Подробности — в [spec.md](spec.md#10-тестирование).

## Если запуск не удался

- «Задайте OPENAI_API_KEY» — впишите ключ в `.env` и перезапустите.
- Ошибки вызовов модели — проверьте сеть, квоту и доступ к моделям из `MODEL_FAST`/`MODEL_REASONING`. Тип ошибки виден в журнале действий.
- `uv` не найден — установите uv и откройте новый терминал.
- Порт занят — используйте `-Port 8001`.
- Qdrant сообщает о блокировке — остановите второй процесс с тем же `DATA_DIR`.
- HTTP 401 — введите токен из `.env`.
- Поиск пуст после смены embeddings — загрузите документы заново или используйте новый `DATA_DIR`.
- PDF без текста — нужен текстовый слой, OCR не поддерживается.
