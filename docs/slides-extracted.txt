Примеры инструментов - Dynamic Tools - Динамические инструменты
Основная идея: Мы задаем условие при котором, ограничиваем набор инструментов, которые “видит” агент. 
Особенно важно для задач, где более 100 инструментов - чтобы сократить время работы агента.
from langchain.agents.middleware import wrap_model_call, ModelRequest, ModelResponse
from typing import Callable

@wrap_model_call
def state_based_tools(
    request: ModelRequest,
    handler: Callable[[ModelRequest], ModelResponse]
) -> ModelResponse:
    """Filter tools based on conversation State."""
    # Read from State: check if user has authenticated
    state = request.state
    is_authenticated = state.get("authenticated", False)
    message_count = len(state["messages"])
    # Only enable sensitive tools after authentication
    if not is_authenticated:
        tools = [t for t in request.tools if t.name.startswith("public_")]
        request = request.override(tools=tools)
    elif message_count < 5:
        # Limit tools early in conversation
        tools = [t for t in request.tools if t.name != "advanced_search"]
        request = request.override(tools=tools)
    return handler(request)

agent = create_agent(
    model="gpt-4.1",
    tools=[public_search, private_search, advanced_search],
    middleware=[state_based_tools])
Вы можете задать любое условие для ограничения списка инструментов. Это также может быть полезно для ограничения функционала для определенных пользователей (админ, пользователь, владелец и тп)

from langchain.agents import create_agent
from langchain.agents.middleware import wrap_tool_call
from langchain.messages import ToolMessage


@wrap_tool_call
def handle_tool_errors(request, handler):
    """Handle tool execution errors with custom messages."""
    try:
        return handler(request)
    except Exception as e:
        # Return a custom error message to the model
        return ToolMessage(
            content=f"Tool error: Please check your input and try again. ({str(e)})",
            tool_call_id=request.tool_call["id"]
        )

agent = create_agent(
    model="gpt-4.1",
    tools=[search, get_weather],
    middleware=[handle_tool_errors])

Advanced Concepts: Memory (Short-term)
Short-term memory - краткосрочная память, 
информация о беседе храниться в рамках одной сессии.
Применение:

Решение проблем:
 можно «забывать» устаревшую информацию или удалять старые сообщения, чтобы сохранить производительность и точность.

@before_model
def trim_messages(state: AgentState, runtime: Runtime) -> dict[str, Any] | None:
    """Keep only the last few messages to fit context window."""
    messages = state["messages"]

    if len(messages) <= 3:
        return None  # No changes needed

    first_msg = messages[0]
    recent_messages = messages[-3:] if len(messages) % 2 == 0 else messages[-4:]
    new_messages = [first_msg] + recent_messages

    return {
        "messages": [
            RemoveMessage(id=REMOVE_ALL_MESSAGES),
            *new_messages
        ]
    }

agent = create_agent(

    tools=your_tools_here,
    middleware=[trim_messages],
    checkpointer=InMemorySaver(),

from langchain_core.messages import trim_messages, RemoveMessage

@before_model
def trim_history(
    state: AgentState,
    runtime: Runtime,
) -> dict[str, Any] | None:
    messages = state["messages"]

    trimmed = trim_messages(
        messages,
        max_tokens=4000,
        token_counter="approximate",
        strategy="last",
        start_on="human",
        end_on=("human", "tool"),
        include_system=True,
        allow_partial=False,
    )

    if len(trimmed) == len(messages):
        return None

    return {
        "messages": [
            RemoveMessage(id=REMOVE_ALL_MESSAGES),
            *trimmed,
        ]
    }

def delete_messages(state):
    messages = state["messages"]
    if len(messages) > 2:
        # remove the earliest two messages
        return {"messages": [RemoveMessage(id=m.id) for m in messages[:2]]}

class CustomState(AgentState):  
    user_name: str

class CustomContext(BaseModel):
    user_id: str

@tool
def update_user_info(
    runtime: ToolRuntime[CustomContext, CustomState],
) -> Command:
    """Look up and update user info."""
    user_id = runtime.context.user_id
    name = "John Smith" if user_id == "user_123" else "Unknown user"
    return Command(update={  
        "user_name": name,
        # update the message history
        "messages": [
            ToolMessage(
                "Successfully looked up user information",
                tool_call_id=runtime.tool_call_id
            )
        ]
    })

agent = create_agent(
    model="gpt-5-nano",
    tools=[update_user_info],
    state_schema=CustomState, 
    context_schema=CustomContext,

from langchain.tools import tool
from langchain.agents import create_agent

remote = Sandbox.create()
backend = E2BSandbox(sandbox=remote)

@tool
def run_python(code: str) -> str:
    """Run Python in an isolated sandbox."""
    backend.upload_files([("/tmp/job.py", code.encode())])
    return backend.execute("python /tmp/job.py").output

## Slide 65
‹#›
FilesystemBackend и LocalShellBackend
Это локальные backend-адаптеры Deep Agents. Ни один из них сам по себе не создаёт sandbox.

FilesystemBackend
• Читает и меняет реальные файлы внутри root_dir.
• Инструменты: ls, read_file, write_file, edit_file, glob, grep.
• Не даёт execute: команды shell не запускаются.

LocalShellBackend
• Наследует все файловые операции FilesystemBackend.
• Добавляет execute: запуск shell-команд на хосте.
• НЕ изолирует процессы: доступны права ОС пользователя.
Подключение к Deep Agents (выбери один backend)

from deepagents import create_deep_agent
from deepagents.backends import FilesystemBackend, LocalShellBackend
backend = FilesystemBackend(root_dir="/workspace", virtual_mode=True)  # или LocalShellBackend(...)
agent = create_deep_agent(model="openai:gpt-4.1", backend=backend)

Важно: virtual_mode=True ограничивает пути файловых tools, но НЕ shell. Для недоверенного кода нужен изолированный sandbox.

Почему не использовать Sandbox всегда?

FilesystemBackend: работа сразу с реальным репозиторием, без переноса файлов и удалённой среды.

LocalShellBackend: запуск pytest/build в уже настроенном dev-окружении, без отдельной VM.

Важно: virtual_mode=True ≠ sandbox. Локальный shell безопасно использовать лишь для доверенных задач.
